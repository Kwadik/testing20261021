[Ссылка на форму сдачи](https://test.invix-solution.com/)

## Функционал сервиса

1. **Разместить товар** \
   В боте для администратора команда «Создать товар»: запрашивает название + фото в одном сообщении. Изображение
   сохраняется в MinIO S3, запись о товаре — в PostgreSQL.
2. **Посмотреть товары (Каталог)** \
   Вкладка/страница каталога на Next.js с заголовком «Каталог» и списком товаров. Работает как в обычном браузере, так и
   внутри Telegram Mini App!

## Обязательный технологический стек

|                                        |                                  |                                             |
|----------------------------------------|----------------------------------|---------------------------------------------|
| **Фронтенд:**<br/>Next.js (App Router) | **Бэкенд:**<br/>FastAPI (Python) | **Telegram-бот:**<br/>aiogram 3.x           |
| **База данных:**<br/>PostgreSQL        | **S3 Хранилище:**<br/>MinIO      | **Интеграция:**<br/>Telegram Mini App (TMA) |

## Логика Telegram-бота

* При старте / обычном обращении бот сообщает: «У меня есть товар» и предлагает открыть Mini App с каталогом.
* Для администратора доступно добавление товара: отправка названия + фотографии в одном сообщении (caption + photo).
* Кнопка Mini App открывает веб-каталог товаров Next.js прямо внутри Telegram.

## Реализованные компоненты

**Frontend**

- Пользовательский интерфейс на Next.js.
- Каталог товаров и отображение карточек товаров.
- Интеграция с backend API для получения и передачи данных.

**Backend**

- REST API на FastAPI.
- Работа с товарами и заказами.
- Сохранение данных в PostgreSQL.
- Асинхронная работа с базой данных.

**Инфраструктура**

- Docker Compose для запуска компонентов проекта.
- Nginx для маршрутизации запросов к API (для мульти-реплик).
- Два экземпляра API для проверки работы за балансировщиком.
- MinIO для объектного хранения фотографий и других файлов.

**Telegram**

- Предусмотрено взаимодействие через Telegram-бота и Mini App.
- Подготовлен сценарий добавления товаров администратором через Telegram.

## Пользовательский сценарий

### 1. Покупка товара

Ранее созданные товары отображаются в каталоге, предусмотрена фильтрация по катекориям. Хоть в структуре БД заложена иерархия категорий, в задании не стал усложнять интерфейс, просто предложены заданные категории в ряд

По кнопке в карточке товара, товар добавляется в корзину, которая достаточно автоматизирована, в ней можно указать кольчество. Сумма покупки также автоматически подсчитывается.

Реализовано создание заказа с сохранением данных в PostgreSQL. При проверке был создан тестовый заказ на три товара
стоимостью 100 рублей каждый.

Итоговая сумма заказа составила 300 рублей. В базе данных проверены статус заказа, валюта, итоговая сумма и количество
товаров.

Реальная оплата не подключалась, что соответствует условиям задания.

### 2. Добавление товара

Так же сделано по очень упрощенной схеме, только для того, чтобы реализовать добавление товара администратором

Работает только через бот. Пользователь, записанный в переменную окружения TELEGRAM_ADMIN_IDS, может отправить боту изображение с подписью, которое станет названием товара. В результате будет создан товар в категории по умолчанию.

## Концепция бэкенда

### 1. Категории

#### `POST /api/v1/categories` — создание категории

Тело запроса (`application/json`):

```
{
  "name": "Посуда",
  "slug": "tableware",
  "parent_id": null
}
```

Поля:

| Поле        | Тип             | Обязательное | Ограничения                                    |
| ----------- | --------------- | ------------ | ---------------------------------------------- |
| `name`      | string          | Да           | 1–100 символов                                 |
| `slug`      | string          | Да           | 1–120 символов; преобразуется в нижний регистр |
| `parent_id` | UUID или `null` | Нет          | Идентификатор родительской категории           |

Пробелы в начале и конце `name` и `slug` удаляются. Пустые после удаления пробелов строки не допускаются.

Успешный ответ: `201 Created`.

Пример ответа:

```
{
  "id": "11111111-1111-4111-8111-111111111111",
  "name": "Посуда",
  "slug": "tableware",
  "parent_id": null,
  "created_at": "2026-10-29T12:00:00Z"
}
```

Если slug уже существует, возвращается `409 Conflict`.

#### `PATCH /api/v1/categories/{category_id}` — изменение категории

Пример запроса:

```
PATCH /api/v1/categories/11111111-1111-4111-8111-111111111111
Content-Type: application/json
```

```
{
  "name": "Керамическая посуда"
}
```

Все поля в `CategoryUpdate` необязательны:

- `name` — строка до 100 символов;
- `slug` — строка до 120 символов;
- `parent_id` — UUID или `null`.

Можно передавать только поля, которые требуется изменить. Если `parent_id` явно передан как `null`, категория становится корневой, если это допускается бизнес-логикой.

Возможные ошибки: `404 Not Found`, `409 Conflict`, `422 Unprocessable Entity`.

#### `GET /api/v1/categories`

Возвращает массив категорий со следующими полями:

- `id` — UUID категории;
- `name` — название;
- `slug` — уникальный идентификатор для URL;
- `parent_id` — UUID родителя или `null`;
- `created_at` — дата и время создания.

### 2. Заказы

#### `POST /api/v1/orders` — создание заказа

Тело запроса (`application/json`):

```
{
  "customer_name": "Иван Иванов",
  "customer_contact": "ivan@example.com",
  "items": [
    {
      "product_id": "22222222-2222-4222-8222-222222222222",
      "quantity": 3
    },
    {
      "product_id": "33333333-3333-4333-8333-333333333333",
      "quantity": 1
    }
  ]
}
```

Поля заказа:

| Поле                 | Тип     | Обязательное | Ограничения             |
| -------------------- | ------- | ------------ | ----------------------- |
| `customer_name`      | string  | Да           | 1–120 символов          |
| `customer_contact`   | string  | Да           | 1–255 символов          |
| `items`              | array   | Да           | От 1 до 100 позиций     |
| `items[].product_id` | UUID    | Да           | Идентификатор товара    |
| `items[].quantity`   | integer | Да           | От 1 до 99 включительно |

Пробелы по краям имени и контакта удаляются. Пустые после этого значения не допускаются. Один и тот же товар нельзя передавать в заказе несколько раз — для него нужно указать одну позицию с нужным количеством.

Пример вызова:

```
curl -X POST "http://localhost:8000/api/v1/orders" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_name": "Иван Иванов",
    "customer_contact": "ivan@example.com",
    "items": [
      {
        "product_id": "22222222-2222-4222-8222-222222222222",
        "quantity": 3
      }
    ]
  }'
```

Замените UUID на идентификатор реально существующего товара.

Успешный ответ: `201 Created`.

Структура ответа (`OrderRead`):

```
{
  "id": "44444444-4444-4444-8444-444444444444",
  "customer_name": "Иван Иванов",
  "customer_contact": "ivan@example.com",
  "status": "new",
  "total_amount": "300.00",
  "currency": "RUB",
  "created_at": "2026-10-29T12:00:00Z",
  "items": [
    {
      "id": "55555555-5555-4555-8555-555555555555",
      "product_id": "22222222-2222-4222-8222-222222222222",
      "product_title": "Кружка",
      "quantity": 3,
      "unit_price": "100.00"
    }
  ]
}
```

Это пример формата ответа, а не реальные идентификаторы. Фактические значения `status`, `currency` и суммы определяются логикой создания заказа и данными товара.

Цена рассчитывается на стороне сервера: клиент передаёт идентификатор товара и количество, а не стоимость. Реальная оплата не производится.

### 3. Товары

#### `GET /api/v1/products`

Возвращает массив активных товаров. Можно передать необязательный параметр `category_id` для фильтрации по категории.

#### `POST /api/v1/products`

Принимает `multipart/form-data`, а не JSON.

| Поле          | Тип    | Ограничения                                 |
| ------------- | ------ | ------------------------------------------- |
| `title`       | string | Обязательное, 1–255 символов                |
| `image`       | file   | Обязательное, JPEG/PNG/WebP, максимум 10 МБ |
| `category_id` | UUID   | Необязательное                              |
| `description` | string | Необязательное, до 5000 символов по схеме   |
| `price`       | number | Необязательное, не меньше 0                 |
| `currency`    | string | Необязательное, 3 символа                   |

`title` обрезается по краям. Описание с одними пробелами нормализуется в `null`, валюта преобразуется в верхний регистр.

Есть нюанс: хотя `category_id` объявлен необязательным в форме и схеме создания, поле `category_id` в ответе `ProductRead` обязательно. Фактическое поведение при создании товара без категории зависит от сервиса и настроек базы данных.

#### `GET /api/v1/products/{product_id}/image`

Возвращает содержимое изображения, а не JSON. Если изображение не найдено, возвращается `404 Not Found`.

## Настройка локальной работы с Telegram Bot

Локальный адрес http://localhost:3000 доступен на компьютере разработчика, но не является публичной ссылкой, которую Telegram сможет открыть на устройстве. Использовался туннель, который создаёт публичный URL и перенаправляет входящие запросы на локальный порт приложения.

Использовалась утилита cloudflared. При успешном создании туннеля в отдельном окне терминала мы получаем ссылку на временный URL типа `https://iowa-reward-logistics-fall.trycloudflare.com` и задаём в переменную .env `TELEGRAM_WEBAPP_URL`

```
cloudflared tunnel --url http://localhost:3000
```

Для задания вебхука используем скрипт, который возьмет адрес из TELEGRAM_WEBAPP_URL

```
cd backend
python scripts/set_webhook.py
```

Также нужно задать ссылку в боте через команду в `@BotFather`:

```
/setmenubutton
```

### 3. Интеграционный тест репозитория товаров

Для интеграционного теста нужна отдельная тестовая база PostgreSQL — `shop_test`. Тестовую базу не следует заменять
рабочей базой `shop`.

Проверить подключение к тестовой базе:

```
docker compose exec postgres \
  psql -U shop_app -d shop_test \
  -tAc "SELECT current_database(), current_user;"
```

Ожидаемый результат:

```
shop_test|shop_app
```

Запуск интеграционного теста:

```
TEST_URL="$(sed -n 's/^DATABASE_URL=//p' .env |
  sed 's#/$##' |
  sed 's#/shop$#/shop_test#')"

TEST_URL="${TEST_URL%/shop_test}/shop_test"

docker compose run --rm \
  -v "$PWD/backend/tests:/app/tests:ro" \
  -e TEST_DATABASE_URL="$TEST_URL" \
  api pytest -q -p no:cacheprovider \
  /app/tests/test_product_repository_integration.py
```

Команда получает параметры подключения из `.env` и подставляет имя тестовой базы. Не публикуйте значение `TEST_URL` или
содержимое `.env`: строка подключения может включать пароль.

Результат последнего запуска: **1 passed**.
